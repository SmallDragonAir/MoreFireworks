# 组合数学 / Combinatorics

本文档推导 `/morefireworks count` 打印的每一个数字，并严格区分三种不同的"数量"：
**数学组合数**、**可生成的合法组合数**、**视觉上可区分的组合数**。

所有计算都由 `com.morefireworks.core.FireworkCombinatorics` 使用 `java.math.BigInteger` 完成，
从不枚举、从不使用 `double` 保存精确值。

This document derives every number printed by `/morefireworks count`, and carefully separates
three different counts: *mathematical*, *generatable* and *visually distinguishable*.

---

## 1. 颜色空间 / The colour space

24 位 RGB，每个通道 8 位：

```
R = 2^24 = 16 777 216
```

颜色用 `int` 的 0x000000–0xFFFFFF 表示。原版 16 种染料颜色只是这 16 777 216 个值中的 16 个，
命名系统对它们使用颜色名，其余颜色回退到 `#RRGGBB`（见 `docs/NAMING.md`）。

## 2. 单颗烟火之星 / A single firework star

一颗星由以下参数确定：

| 参数 | 取值数量 | 说明 |
| --- | --- | --- |
| 爆炸形状 | 5 | 小球形、大球形、星形、苦力怕形、爆裂形（对应原版 `FireworkExplosion.Shape`） |
| 闪烁 | 2 | 开 / 关 |
| 拖尾 | 2 | 开 / 关 |
| 初始颜色列表 | `A = Σ_{i=1..8} R^i` | 长度 1–8，**有序**，允许重复 |
| 渐变颜色列表 | `B = Σ_{j=0..8} R^j` | 长度 0–8，**有序**，允许重复 |

因此

```
E = 5 × 2 × 2 × A × B = 20 × A × B
```

其中

```
A = R + R² + R³ + … + R⁸
B = 1 + R + R² + … + R⁸
```

`A` 与 `B` 用等比数列闭式求值，代价与长度呈对数关系，而不是逐项累加：

```
Σ_{i=from..to} base^i = (base^(to+1) − base^from) / (base − 1)
```

### 精确数值

```
A = 6277102109531122221293464242049138210298616033742734491648      (58 位)
B = A + 1 = 6277102109531122221293464242049138210298616033742734491649
E = 788040217869601294242360580346343349682488349330329498066448862094047631173495428966639528457166958517707114324951040
  ≈ 7.8804e+116                                                     (117 位)
```

## 3. 火箭 / A rocket

飞行等级 `d ∈ {1,2,3}`，原版工作台约束给出可携带的星数上限：

```
maxStars(d) = 8 − d      →      7 / 6 / 5
```

星序**有意义**（红色星形→蓝色大球形 与 蓝色大球形→红色星形 是两种不同组合），
且**允许重复**，所以长度为 `n` 的火箭有 `E^n` 种。至少携带一颗星的火箭总数：

```
T = Σ_{d=1..3} Σ_{n=1..8−d} E^n
```

逐飞行等级：

| 飞行等级 | 星数上限 | 数量 | 位数 |
| --- | --- | --- | --- |
| 1 | 7 | `1.8873e+818` | 819 |
| 2 | 6 | `2.3949e+701` | 702 |
| 3 | 5 | `3.0391e+584` | 585 |
| 合计 `T` | | `1.8873e+818` | 819 |

不含任何爆炸效果的普通火箭只有 3 种（1/2/3 级各一种），所以物品变体总数：

```
Total = T + 3 = 1.8873e+818     （819 位十进制数字）
```

> 注意 `T` 与 `Total` 的十进制位数相同：`+3` 只改变末位，不改变量级。这正是本项目
> "天文数字级变体"的直观体现。

## 4. 三种"数量"的区别 / Three different counts

### 4.1 数学组合数（mathematical）

上面算出的 `E`、`T`、`Total`。它把每一组不同参数都算作不同，包括：

* 初始颜色顺序不同（`[红, 蓝]` vs `[蓝, 红]`）；
* 颜色列表里重复同一个颜色（`[红, 红]` vs `[红]`）；
* 视觉上可能完全一样的参数组（例如全透明/极暗颜色的细微差别）。

### 4.2 可生成的合法组合数（generatable）

`Total` 中每一个组合都能被 `/morefireworks random`、随机生成器或数据组件构造出来，
且没有注册表限制（只有 2 个物品，参数在数据组件里）。因此

```
generatable = Total
```

唯一的约束是容量上限（`FireworkLimits`），而这些上限恰好等于数学模型里的上限
（7 星、8+8 颜色、1024 字符），所以不会丢失合法组合。

### 4.3 视觉上可区分的组合数（visually distinct）

原版爆炸的每一颗粒子从颜色列表里**随机**取一个颜色，因此：

* 颜色列表的**顺序不可观察**；
* 颜色的**重数可观察**（出现频率不同）；
* 初始颜色与渐变颜色都遵循同一规则。

所以可观察的颜色对象是**多重集**（multiset），长度为 `k` 的多重集数量为

```
C(R + k − 1, k)
```

于是视觉上不同的星数为

```
E_visual = 20 × (Σ_{k=1..8} C(R+k−1, k)) × (Σ_{k=0..8} C(R+k−1, k))
         ≈ 4.8474e+107        (108 位)
```

视觉上不同的火箭数为 `6.2887e+753`（754 位）。

**结论：** 数学组合数比视觉可区分组合数大约 `10^65` 倍。多出来的部分是"数据不同但视觉相似"
的组合——它们被完整保留（因为数据必须无损），但项目**不会**声称它们视觉上互不相同。

## 5. 边界情况 / Edge cases

| 情况 | 处理 |
| --- | --- |
| 颜色列表为空 | 非法：`StarSpec` 要求至少 1 个初始颜色 |
| 颜色数 > 8 | 非法：构造时抛 `IllegalArgumentException`，解码时转为数据错误 |
| 颜色值超出 0xFFFFFF | 非法：`RgbColors.isValid` 拒绝 |
| 星数超过 `8 − flight` | 非法：`RocketSpec` 拒绝 |
| 普通火箭（0 颗星） | 合法，单独计入 `plainRockets` |
| 极长名称 | 全名分段展示，spec 字符串上限 1024 字符 |
| 大数据 | 一律 `BigInteger`；`double` 只用于科学计数法的**展示** |

## 6. 为什么不能枚举 / Why enumeration is impossible

`T` 有 819 位十进制数字。把它写成 1 后面跟 818 个 0，即使每纳秒枚举一个组合，也需要
约 `10^800` 年。因此实现只允许：

1. 用闭式计算总数；
2. 用随机/确定性生成器**抽样**具体组合；
3. 用数据组件保存**已经生成**的那一个组合。

任何"注册所有变体"或"预生成 JSON"的做法在物理上都不可能，这也是本项目的设计前提。
